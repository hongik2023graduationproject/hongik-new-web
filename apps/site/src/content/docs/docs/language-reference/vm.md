---
title: "바이트코드 VM"
---

hong-ik에는 실행 엔진이 두 개 있습니다. **바이트코드 VM이 기본 실행 엔진**이고, 트리워킹 인터프리터는 `--eval` 플래그로 고를 수 있습니다. 웹 플레이그라운드와 문서의 실행 예제도 VM으로 실행됩니다.

## 사용법

```bash
./cmake-build-debug/HongIk filename.hik          # VM (기본)
./cmake-build-debug/HongIk --eval filename.hik   # 트리워킹 인터프리터
./cmake-build-debug/HongIk                       # REPL (VM)
./cmake-build-debug/HongIk --eval                # REPL (트리워킹)
```

`--vm` 플래그는 예전 명령과의 호환을 위해 받아들이지만 아무 효과가 없습니다(이미 VM이 기본입니다).

## 작동 원리

VM은 소스코드를 바이트코드로 컴파일하고, 피홀 최적화를 거친 뒤 스택 기반 가상 머신에서 실행합니다:

```text
소스코드(한글) -> Lexer -> Parser -> Compiler -> VM (기본) -> 결과
                                  \-> Evaluator (--eval, 트리워킹) -/
```

## 두 엔진 비교

| 특성 | 바이트코드 VM | 트리워킹 인터프리터 |
|------|---------------|----------|
| 실행 방식 | 바이트코드 컴파일 후 실행 | AST 직접 순회 |
| 플래그 | (없음, 기본) | `--eval` |
| 웹 플레이그라운드 | 사용 | 사용 안 함 |
| 속도 | 더 빠름 | 느림 |

두 엔진은 연산자·선언 타입 검사·블록 스코프 등 언어 규칙이 같도록 맞춰져 있습니다. 정적 타입 검사(`--type-check=off|warn|strict`, 기본 `warn`)는 엔진과 관계없이 실행 전에 이루어집니다.

## VM에서 아직 지원하지 않는 기능

아래 기능은 현재 트리워킹 인터프리터(`--eval`)에서만 동작합니다. VM(웹 포함)에서는 `존재하지 않는 식별자` 오류가 납니다.

- 고차 내장 함수 `매핑`, `걸러내기`, `줄이기` — [고차 함수](/docs/builtin-functions/higher-order/) 참고. `각각` 반복문으로 대신할 수 있습니다.
- 부모 클래스 메서드 호출 `부모.메서드()` — [상속](/docs/language-reference/inheritance/) 참고.

그 밖의 기능 — 산술·비교·논리 연산, 변수, 조건문(`아니면 만약` 포함), 반복문, 함수와 클로저, 클래스와 상속, 예외 처리(함수 안의 `시도`/`실패` 포함), 문자열 보간, `가져오기`(CLI), 내장 함수 45종 — 는 VM에서 동작합니다.
